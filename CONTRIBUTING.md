# Contributing

Submissions are welcome when a tool has a concrete efficiency story. Good reasons for inclusion include reducing:

* CPU, RAM, disk, or network requirements
* AI, token, or context overhead
* command or build noise
* infrastructure requirements
* setup complexity
* repetitive work
* workflow friction

There are no arbitrary requirements for project age, GitHub stars, or number of maintainers. Projects should nevertheless be usable today and should not appear abandoned or obviously broken. Early-stage projects may be included when their efficiency idea or implementation is compelling.

This list is editorial, and inclusion is ultimately at the maintainer's discretion. In a submission, disclose whether you are the author, maintainer, employee, sponsor, or otherwise affiliated with the project.
